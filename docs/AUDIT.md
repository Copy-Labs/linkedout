# LinkedOut V1 — Audit

**Date:** 2026-11-25
**Scope:** everything implemented for V1 — Convex backend, Cloudflare Worker, React SPA, deployment configuration and the live production deployment.

## Resolution (same day)

The three high-severity findings below have been fixed and deployed to both dev and production:

- **H1** — `companyStats` and `platformStats` documents hold denormalized counters, updated transactionally on submit/moderation/reaction/takedown/erase. `companyScorecard` and `homeStats` now read one small document instead of scanning the stories table. `stats.rebuild` migrates existing data.
- **H2** — `stories.erase` permanently deletes a story plus its reactions, reports and moderation results, and writes a content-free `auditLog` entry. The review queue exposes it behind a confirmation.
- **H3** — the Worker's `/api/admin/session` exchanges the permanent `ADMIN_SECRET` for a 30-minute HMAC token; Convex verifies the token with Web Crypto. The permanent secret never reaches the browser, the session endpoint is rate limited, and moderation/takedown/erase actions write audit entries.

Verified end to end: admin session issued in dev and prod, test story erased (document gone, counters decremented, audit entry present), lint/typecheck/build pass, deployed SPA and Worker smoke-tested.

### Medium findings also resolved

- **M1** — hourly Convex cron deletes expired/used tokens in batches via `submissionTokens.by_expires`.
- **M2** — the Worker checks Turnstile `hostname` (and `action` when the provider returns one) against configured values; production is pinned to the deployed hostname.
- **M3** — reports now require the same edge-issued single-use token as submissions.
- **M4** — HSTS, `nosniff`, Referrer-Policy, X-Frame-Options, Permissions-Policy and a report-only CSP are applied to Worker responses and to static assets via `public/_headers`.
- **M5** — `shadcn` moved to devDependencies and a `minimatch` override applied; `pnpm audit` is now clean.
- **M6** — Vitest added with 13 tests covering moderation rules, toxicity scoring and admin session tokens; root `pnpm test` runs them.
- **M7** — Worker types are generated by `wrangler types`, a dedicated `tsconfig.worker.json` typechecks them, and observability is explicitly disabled for the zero-logging posture.

While verifying M2/M3 in production I also fixed a real token-flow bug: `getResponse()` could return an already-consumed Turnstile token, so `requestToken()` now triggers a fresh `execute()` and polls for the new token.

### Low findings also resolved

- **Company link bug** — stories now store `companySlug`; the card links to the canonical slug, and a one-off backfill patched existing stories.
- **robots.txt / SEO** — real `robots.txt` allows `/` and disallows `/review`; Lighthouse SEO is now 1.0.

- **Demo companies** — an admin `companies.deleteEmpty` mutation removed the two leftover records; production now has 0 companies and 0 stories.

## Verdict

The MVP is **functionally complete and genuinely works end to end**: real Turnstile verification, single-use tokens, rule moderation, human review, reactive feeds/scorecards, and a production deploy pinned to the linkedout account. The privacy-shaped decisions (no PII columns, hashed tokens, no accounts) are the right ones.

It is **not yet hardened for real-world abuse, scale, or legal scrutiny**. The three issues I would fix before inviting real users are the unbounded aggregates, the absence of a hard-delete/erasure path, and the admin-auth pattern. None of these block the demo; all of them matter for a platform that hosts anonymous allegations about employers.

## High severity

### H1. ~~Unbounded aggregate queries will break as data grows~~ — FIXED

`convex/stats.ts` — `companyScorecard()` collects **every approved story for a company**, and `homeStats()` collects **every approved story and every company** on each subscription update.

Convex limits a transaction to **32,000 documents scanned / 16 MiB read**. Once those are crossed these reactive queries throw, taking the home page and company pages with them. Even before the limit, every new story or reaction re-runs full-collection scans for every subscribed client.

**Fix:** maintain denormalized counters (`companyStats`, global stats) updated transactionally in `stories.submit`, `moderation.apply`, `moderation.override`, `reactions.add` and `reports.resolve`; read the small counter document reactively instead of scanning the collection.

### H2. ~~No hard delete / erasure path~~ — FIXED

`convex/reports.ts` — `resolve("removed")` only flips the story to `rejected`. The body, tags and related moderation records remain in Convex forever.

For an anonymous-whistleblowing product this conflicts with the privacy promise and with any "right to erasure" expectation. A company that wins a takedown review reasonably expects the content to be gone, not merely hidden.

**Fix:** admin-only `stories.erase` that deletes the story plus its `reactions`, `reports` and `moderationResults`, writing a minimal audit record (story ID + reason + timestamp, no content).

### H3. ~~Admin authentication is a shared secret passed from the browser~~ — FIXED

`src/routes/review.tsx` keeps `ADMIN_SECRET` in React state and sends it as an argument to `moderation.pending`, `moderation.override` and `reports.resolve`. `convex/lib/auth.ts` compares it in constant time — but the secret is still visible in DevTools/network payloads, may appear in Convex logs, has no rate limiting, and produces no audit trail of who changed a verdict.

A 256-bit secret is not brute-forceable, but this is the wrong shape for a moderation console.

**Fix:** proper admin authentication (Convex Auth with a single admin session or a server-issued short-lived token in an HttpOnly cookie), plus a moderation audit log.

## Medium severity

### M1. ~~`submissionTokens` grows without bound~~ — FIXED

`convex/tokens.ts` — `issue()` inserts a token record; `consume()` marks it used but nothing ever deletes used or expired records. On the free Convex tier (0.5 GB storage) this is a slow leak.

**Fix:** scheduled cleanup mutation deleting records with `usedAt` set or `expiresAt < now`, older than ~24h.

### M2. ~~Turnstile verification checks only `success`~~ — FIXED

`worker/index.ts:58` — the Worker accepts any successful token from the siteverify endpoint. It does not verify `hostname` or `action`. Anyone able to embed our site key on another origin could mint tokens that pass our endpoint.

**Fix:** require `result.hostname === "linkedout-edge.linkedout-fbf.workers.dev"` (configurable) and check the action returned matches the expected one.

### M3. ~~Reports are unthrottled~~ — FIXED

`convex/reports.ts` — `reports.create` requires no token and has no rate limit, so one client can flood the review queue.

**Fix:** reuse the edge token flow for reports, or apply the Convex rate-limiter component keyed by a one-way hash.

### M4. ~~No security headers~~ — FIXED

The deployed Worker sends no CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, or `frame-ancestors`. Lighthouse's Best Practices score ignores this. Turnstile itself emits `data:,` CSP warnings in the console, so a strict CSP needs careful `connect-src` allowances for `challenges.cloudflare.com` and the Convex WebSocket.

**Fix:** add headers on HTML responses in the Worker; roll out CSP in `Content-Security-Policy-Report-Only` mode first.

### M5. ~~`shadcn` CLI is a runtime dependency~~ — FIXED

`packages/ui/package.json` lists `shadcn` under `dependencies`. It is a build-time CLI and pulls `minimatch@10.2.6`, which has a moderate DoS advisory from `pnpm audit`. Nothing in the shipped app needs it at runtime.

**Fix:** move `shadcn` to `devDependencies`, regenerate the lockfile, re-run audit.

### M6. ~~No automated tests~~ — FIXED

Every verification so far was manual (browser + CLI). The moderation rules, token single-use semantics and scorecard math have no regression safety net.

**Fix:** add unit tests for `classifyRules` and scorecard aggregation, plus a small integration smoke test for the token → submit → moderate flow.

### M7. ~~Worker types are hand-written~~ — FIXED

`worker/index.ts` declares `type Env` manually. It can drift from `wrangler.jsonc`. Workers Logs/Traces are also not explicitly configured — a deliberate privacy tradeoff, but one to make explicitly rather than by omission.

**Fix:** generate types with `wrangler types`; decide and document the observability posture.

## What is done well

- No IP, user-agent, email, account or device fields anywhere in the schema; only SHA-256 hashes of random tokens are stored.
- Rate-limit key is a salted, daily-rotating hash used transiently at the edge — never persisted.
- Turnstile is verified before any Convex write; single-use tokens prevent direct Convex API bypass.
- `meTooCount` is incremented transactionally with an idempotency index — reactive without a separate counter service.
- Search uses Convex search indexes; feed uses pagination; no over-fetching.
- React escapes all story text; no `dangerouslySetInnerHTML`.
- Lighthouse accessibility and best-practices scores are both 1.0.
- Production deploy is pinned by `account_id`; Preview URLs disabled; real widget scoped to the exact hostname; no source maps exposed.
- Convex dev/prod separation, secrets in gitignored files, legal draft pages with explicit "lawyer review required" notices.
