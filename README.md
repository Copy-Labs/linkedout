# LinkedOut

An anonymous workplace-transparency platform V1: people share why they left a
toxic workplace, job seekers search companies and see an aggregate toxicity
scorecard. No accounts, no personal data collected.

Architecture and rationale: [`docs/BLUEPRINT.md`](docs/BLUEPRINT.md).

## Stack

- **Frontend:** Vite 8 + React 19 + shadcn/ui (Tailwind 4, base-ui) + React Router
- **Data + realtime:** Convex (reactive queries, mutations, scheduled actions, full-text search)
- **Edge:** Cloudflare Worker (Hono) on Workers static assets — Turnstile verification, rate limiting, single-use tokens
- **Moderation:** deterministic rules + a human review queue; AI sits behind an interface
- **Monorepo:** pnpm workspaces + Turbo (`apps/web`, `packages/ui`)

## Local development

```bash
pnpm install
cd apps/web
npx convex dev                 # first run creates the dev deployment and .env.local
pnpm dev:edge                  # Worker at http://localhost:8787
pnpm dev                       # Vite SPA (usually http://localhost:5173)
```

Vite proxies `/api/*` to the Worker on port 8787. In production, the Worker
serves both the built SPA and `/api/*`.

### Environment

- `.env.local` (generated by Convex): `VITE_CONVEX_URL`, `VITE_TURNSTILE_SITE_KEY`
- `.dev.vars` (local, gitignored): `WORKER_SECRET`, `TURNSTILE_SECRET_KEY`, `ADMIN_SECRET`
- Convex deployment env: `WORKER_SECRET`, `ADMIN_SECRET` (`npx convex env set …`)

Development uses Cloudflare's public Turnstile test keys (always pass). Replace
them with real keys before deploying.

The review queue lives at `/review`. Paste the `ADMIN_SECRET` once: the Worker
exchanges it for a 30-minute HMAC session token, so the permanent secret is
never kept in the browser. The queue can approve/reject/flag or permanently
delete stories and resolve takedown requests.


Production `ADMIN_SECRET` / `WORKER_SECRET` are in the gitignored `.prod.vars`.

## Privacy and legal

The schema contains no IP, user-agent, email, account or device fields. Turnstile
is privacy-friendly and the edge uses only a rotating salted hash of the IP as a
transient rate-limit key. Images are not supported, so there is no EXIF surface.
Expired submission tokens are purged by an hourly cron. HSTS, `nosniff`,
Referrer-Policy, X-Frame-Options, Permissions-Policy and a report-only CSP are
applied to both SPA and API responses. Workers observability is explicitly disabled.

Errors are reported to PostHog from the React error boundary and from failed
mutations. PostHog runs with memory-only persistence, no session replay, no
autocapture and no automatic pageviews; pageviews are sent with the pathname
only. Set `VITE_POSTHOG_PROJECT_TOKEN` and `VITE_POSTHOG_HOST` in `.env.local`.

The ToS, privacy policy and takedown page are drafts. **They require review by a
qualified lawyer in your jurisdiction before launch.**
